개발 인수 사항

각 항목 아래의 참고 파일을 열어 보면 실제 마크업과 동작을 바로 확인할 수 있습니다. 경로는 모두 contents 폴더 기준이고, 화면별 상태 전환 방법은 HTML 안의 [항목명] 주석에도 적혀 있습니다. 개발이 필요한 부분에는 "(개발 필요)"라고 표시했습니다.

개발필수 입력 검사 통과 후 안내 팝업 (data-after-popup)

  • 접수 버튼([data-validate-btn])에 data-after-popup="팝업이름"을 달면, 필수 입력 검사를 통과한 뒤 바로 이동하지 않고 해당 레이어 팝업(.layer-popup[data-popup="팝업이름"])을 먼저 엽니다. 검사에 걸리면 팝업은 열리지 않고 기존처럼 경고 토스트만 뜹니다
  • 팝업의 [확인](.confirm-yes)을 누르면 접수 버튼의 href(다음 단계)로 이동하고, [취소]는 팝업만 닫고 신청서에 머뭅니다. 이동 경로는 개발에서 연결(href 입력)
  • 팝업을 코드로 열 때는 window.openLayerPopup("팝업이름")을 호출합니다. 검사를 서버나 자체 로직으로 처리하는 경우, 통과 후 이 함수 한 줄로 같은 팝업을 띄울 수 있습니다(data-validate-btn과 data-after-popup은 삭제)
  • 이 속성이 없는 기존 접수 버튼은 동작이 바뀌지 않으며, 다른 팝업의 열기·닫기·확인 처리도 그대로입니다
  • 화면 검사는 퍼블리싱 단계의 편의용이므로 서버에서도 같은 항목을 다시 검증해야 합니다

개발초등부 연합회현황 (지도 · 표 DB 연동)

  • 페이지 맨 아래 <script>에 테스트용 더미 데이터와 화면 전환 샘플(3개 지구)이 들어 있습니다.
  • 핀을 누르면 해당 핀에 .on이 붙고 document에 parish:select 이벤트(본당명, 요소)가 발생합니다. 이때 [지구 임원] 표(.union-officer)를 숨기고 [본당 정보] 표(.union-parish, 제목 "OO 성당", 구분 · 이름 · 세례명)를 출력합니다. 기본 본당이 없는 지구에서는 [지구 임원] 표를 출력하고, 표시 전환은 hidden 속성으로 합니다
  • 지도(#map)는 kakao-maps.js의 initKakaoMapParish()로 띄웁니다. 핀 위치는 data-lat · data-lng(좌표) 또는 data-address(주소) 중 하나를 입력하며, 좌표가 없으면 주소를 카카오 지오코더로 변환해서 표시합니다. 더미 데이터는 좌표와 주소 방식을 섞어 두었고, 좌표 · 주소는 대략적인 위치입니다
  • 지구마다 기본으로 선택해 둘 본당 한 곳의 .parish-item에 data-default 속성을 붙입니다(예: <li class="parish-item" data-name="명동" data-address="…" data-default></li>). 한 지구에 한 곳만 붙이며, 여러 개면 마지막 항목이 적용됩니다
  • data-default가 있는 본당은 페이지 진입, 지구 선택, 새로고침 시 지도가 뜬 뒤 해당 핀이 강조(.on)되고 그 본당의 [본당 정보] 표가 바로 출력됩니다. 붙이지 않은 지구는 선택된 핀 없이 [지구 임원] 표를 출력합니다. 기본 본당을 정하는 규칙(첫 번째 본당 또는 별도 설정값)은 개발에서 정합니다
  • 더미 데이터의 isDefault: true는 샘플 스크립트가 data-default로 바꿔 넣는 값입니다(제01중구-용산지구 명동, 제02서대문-마포지구 서대문, 제04성북지구 성북동)

개발선택 상자 선택 초기화 (data-reset)

  • 선택 사항인 선택 상자(.select-box-wrap)에 data-reset을 달면, 목록 맨 위에 처음 안내 문구(예: "숙소 선택")가 초기화 항목(li.reset)으로 자동 추가됩니다. 값을 고른 뒤에도 이 항목을 누르면 아무것도 선택하지 않은 처음 상태로 돌아갑니다
  • 초기화하면 안내 문구가 다시 표시되고, 숨은 입력값(input[type="hidden"])은 빈 값이 되며 change 이벤트가 발생합니다
  • 항목 이름은 선택 상자의 처음 안내 문구입니다. 처음부터 값이 선택돼 있는 경우(예: 명단 작성의 학년)는 data-reset="학년"처럼 문구를 지정할 수 있습니다
  • 필수 항목(전화 앞자리, 생년월일 등)에는 달지 않았습니다. 목록 항목은 common.js가 넣으므로 서버에서 목록을 만들 때 초기화 항목을 따로 넣지 않습니다

개발연결이 필요한 부분 (화면만 있고 처리는 없음)

  • 단계 간 연결: 신청 목록의 신청중 버튼은 확인 팝업과 토스트까지만 동작하고, 약관동의의 회원/비회원 버튼 href는 비어 있으며, 접수완료 이후 신청 완료 페이지 이동도 없습니다. 페이지 간 연결과 서버 처리를 연결해야 합니다

  • 저장·삭제·취소 처리: 명단 저장, 신청취소, 예약취소는 확인 팝업이나 토스트까지만 동작합니다. 실제 처리는 [예] 클릭 또는 저장 버튼에 연결합니다
